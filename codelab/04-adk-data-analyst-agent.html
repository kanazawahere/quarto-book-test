    5  Data Analyst Agent với ADK và BigQuery

    Làm thật 2026-08-27 — và lần này làm trên máy Linux headless (SSH, không Cloud Shell), nên chương này có nguyên một mỏ mìn mà bản gốc không bao giờ gặp: xác thực ADC không có browser. Bản gốc: codelab của Google. Phiên bản lúc làm: google-adk 2.8.0 (mới hơn hẳn bản codelab viết — vài import đã đổi tên).

    Mục tiêu: dựng agent phân tích dữ liệu (ADK + Gemini) qua 4 nấc: chat cơ bản → đọc PDF → tìm web (google_search) → tự truy vấn BigQuery trên dataset public cms_medicare (dữ liệu Medicare Mỹ). Chi phí thật: ~0 đồng (query public dataset trong 1TB free tier, vài chục call Gemini Flash).

    5.1 Tiến độ của bạn

    # Môi trường
- venv Python 3.12 + uv pip install google-adk
- ADC sống (máy thật headless: xem MÌN #1)
# 4 nấc agent
- adk create bằng flags (khỏi trả lời TUI)
- Chat cơ bản trả lời được
- Nạp PDF, agent tóm tắt đúng
- google_search trả kết quả web tươi
# BigQuery
- Cài đúng extra google-adk[bigquery-analytics]
- Agent tự khám dataset + chạy SQL đúng project
- Cleanup (đừng rm -rf ~/.cache! — xem MÌN #0)

    5.2 🔴 MÌN #0 — đừng chép mù lệnh dọn dẹp của Cloud Shell

    Codelab mở đầu bằng rm -rf ~/.cache — đó là lệnh dọn quota đĩa Cloud Shell. Chạy nguyên xi trên máy thật là phá cache của cả hệ thống (pip, browser, font…). Đọc lệnh trước khi chép, nhất là lệnh rm.

    5.3 Bước 1 — Môi trường

    mkdir -p ~/ai-agents-adk && cd ~/ai-agents-adk
uv venv --python 3.12 && source .venv/bin/activate
uv pip install google-adk

    5.4 🔴 MÌN #1 — máy headless không có ADC, và đường vòng SA-key cũng bị khoá

    adk gọi Vertex AI qua Application Default Credentials. Trên máy không có browser, gcloud auth application-default login chết ngay (đòi mở trình duyệt). Đường vòng kinh điển — tạo service account key — cũng chết nốt, lỗi nguyên văn:

    FAILED_PRECONDITION: Key creation is not allowed on this service account.
type: constraints/iam.disableServiceAccountKeyCreation

    Org policy mặc định của project mới (2024+) cấm tạo SA key. Cách vượt đã chạy thật: gcloud CLI vốn đã đăng nhập rồi — móc refresh token của chính nó ra làm ADC:

    python3 - <<'EOF'
import sqlite3, json, os
db = os.path.expanduser("~/.config/gcloud/credentials.db")
row = sqlite3.connect(db).execute("select value from credentials").fetchone()
cred = json.loads(row[0])
adc = {
  "type": "authorized_user",
  "client_id": cred["client_id"],
  "client_secret": cred["client_secret"],
  "refresh_token": cred["refresh_token"],
  "quota_project_id": os.popen("gcloud config get-value project").read().strip(),
}
out = os.path.expanduser("~/.config/gcloud/application_default_credentials.json")
json.dump(adc, open(out, "w"), indent=2)
print("ADC OK:", out)
EOF
gcloud auth application-default print-access-token > /dev/null && echo "ADC sống"

    Nhớ quota_project_id — thiếu là BigQuery client kêu thiếu quota project.

    5.5 Bước 2 — Tạo agent (không cần trả lời TUI)

    Mẹo bản gốc không nói: adk create có flags, automation dùng thẳng:

    adk create data_analyst_agent --model gemini-2.5-flash \
  --project $(gcloud config get-value project) --region us-central1

    Lưu ý version: adk 2.8.0 ghi .env bằng biến mới GOOGLE_GENAI_USE_ENTERPRISE=1 (tài liệu cũ là GOOGLE_GENAI_USE_VERTEXAI=1 — cả hai đều được hiểu, đừng hoảng khi diff).

    Chat thử: có UI (adk web) hoặc headless ~15 dòng Python với InMemoryRunner. “Upload” PDF khi headless = types.Part.from_bytes(data=..., mime_type='application/pdf') đặt TRƯỚC phần text trong cùng message — kết quả thật: agent tóm tắt đúng file PDF báo cáo healthcare 2.4MB.

    5.6 Bước 3 — Thêm google_search

    google_search là tool built-in cắm thẳng vào Agent. Nhưng chú ý cho bước sau: built-in tool của Gemini không đứng chung với function tool khác trong 1 agent — nên khi trộn với BigQuery toolset, codelab phải bọc nó trong agent con qua AgentTool. Đó là kiến trúc bắt buộc, không phải kiểu cách.

    5.7 🔴 MÌN #2 — BigQuery toolset: cài đúng TÊN extra, và py_compile không cứu được bạn

    Chép nguyên code BigQuery của codelab chạy là chết:

    ModuleNotFoundError: No module named 'google.cloud'

    Cài google-cloud-bigquery xong chết tiếp: ImportError: cannot import name 'dataplex_v1'. Gốc: adk 2.8.0 không bundle BigQuery client, và tên extra đúng là:

    uv pip install "google-adk[bigquery-analytics]"

    (KHÔNG phải [bigquery]. Cài tay thì đủ bộ 3: google-cloud-bigquery db-dtypes google-cloud-dataplex.)

    Mìn trong mìn: ADK import lazy — py_compile PASS mà runtime mới nổ. Bài “py_compile trước khi chạy” của chương 3 vẫn đúng cho lỗi cú pháp, nhưng với toolset ADK phải chạy thật 1 câu mới tin được.

    5.8 🔴 MÌN #3 — agent tự bill query vào… project của người khác

    Mìn tinh vi nhất bài: hỏi agent query bigquery-public-data.cms_medicare → tool trả permission error, agent xin lỗi vòng vo (thậm chí tự bịa thử project_id: 'gcp-data-ai'). Gốc: tham số project_id của execute_sql là project TRẢ TIỀN cho query — LLM đoán nhầm nó là project chứa data, nên cố bill vào bigquery-public-data (dĩ nhiên không có quyền).

    Fix 1 câu: nói rõ trong prompt hoặc instruction của agent: “Run all SQL queries in my project <PROJECT_ID>” → chạy ngọt ngay. Kết quả thật: agent tự chuỗi get_dataset_info → list_table_ids → execute_sql, trả đúng top-5 DRG theo lượt xuất viện (SEPTICEMIA 521.358 lượt…) và chi phí trung bình thay khớp ở California = $21.389,14.

    5.9 Dọn dẹp

    rm -rf ~/ai-agents-adk

    Mẹo ít ai biết: nếu lỡ xoá service account trước khi gỡ IAM binding, member trong policy biến thành deleted:serviceAccount:…?uid=… — phải remove-iam-policy-binding bằng đúng chuỗi deleted đó (lấy từ get-iam-policy --flatten="bindings[].members"), gõ tên cũ là không ăn.

    5.10 Ôn nhanh

    Q: Máy headless (không browser), cần ADC cho ADK/Vertex. gcloud auth application-default login chết, tạo SA key bị org policy chặn. Còn đường nào?
- Chịu thua, phải qua Cloud Shell
-* Móc refresh token từ credentials.db của gcloud (đã đăng nhập sẵn) tự ghi thành application_default_credentials.json kiểu authorized_user
- Tắt org policy đi
E: gcloud CLI đã có refresh token hợp lệ trong SQLite — dựng ADC từ nó, nhớ kèm quota_project_id.

Q: Code BigQuery toolset của codelab chạy ra ModuleNotFoundError google.cloud dù py_compile PASS. Vì sao py_compile không bắt được?
- py_compile bị lỗi
-* ADK import lazy (__getattr__) — lỗi thiếu module chỉ nổ lúc runtime thật sự chạm tool, compile không đụng tới
- Python version sai
E: Với toolset ADK phải chạy thật 1 câu mới tin; và extra đúng tên là google-adk[bigquery-analytics].

Q: Agent query dataset public bị permission error dù dataset ai cũng đọc được. Gốc ở đâu?
- Dataset public cũng cần xin quyền
-* Tham số project_id của execute_sql là project TRẢ TIỀN — LLM đoán nhầm thành project chứa data nên bill vào bigquery-public-data
- BigQuery đang bảo trì
E: Nói rõ "Run all SQL queries in my project X" trong instruction là hết — public data đọc free nhưng compute phải bill vào project của mình.

Q: Lệnh đầu tiên của codelab là rm -rf ~/.cache. Chạy trên máy thật được không?
- Được, lệnh chuẩn của Google mà
-* KHÔNG — đó là lệnh dọn quota đĩa của Cloud Shell; máy thật sẽ mất cache pip/browser/font của cả hệ thống
- Chỉ cần sudo là an toàn
E: Codelab viết cho môi trường Cloud Shell dùng-xong-vứt. Đọc lệnh rm trước khi chép, luôn luôn.
