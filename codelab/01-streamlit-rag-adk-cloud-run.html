    2  Streamlit RAG Agent với Google ADK trên Cloud Run

    Làm thật 2026-08-07 (Hack2Skill GenAI Academy, Track 1 — deploy coffee-barista). Bản gốc: codelab của Google. Chương này ghi lại đường đi thật kèm 4 quả mìn IAM mà bản gốc không nhắc — mỗi quả tốn 1 vòng deploy-fail để lộ ra.

    Mục tiêu: dựng AI barista agent (Google ADK + Gemini + Streamlit), RAG trên menu quán cà phê, chạy trên Cloud Run. Chi phí thật: dưới 1 USD.

    2.1 Tiến độ của bạn

    # Chuẩn bị
- Có project GCP đã bật billing
- Gỡ mìn IAM TRƯỚC khi deploy (mục 🔴 MÌN #0 bên dưới)
- Bật 3 API (run, aiplatform, cloudbuild)
# Dựng agent
- Tạo menu.json + kiểm JSON hợp lệ
- Tạo requirements.txt, agent.py, app.py
# Deploy
- Tạo service account + cấp aiplatform.user
- gcloud run deploy thành công
- Test 3 câu RAG (in-menu, out-of-menu, allergen)
# Dọn dẹp
- Xoá service + service account khi xong

    2.2 🔴 MÌN #0 — cấp đủ IAM MỘT LƯỢT trước khi deploy (quan trọng nhất chương)

    Trên project GCP mới tạo, Google không còn tự cấp role Editor rộng cho service account mặc định của Compute Engine (“secure by default”). Hệ quả thật đã nếm: 4 lần deploy fail liên tiếp, mỗi lần lộ ra đúng 1 role thiếu — lỗi sau chỉ hiện khi lỗi trước được vá, nên đi từng lỗi tốn cả buổi.

    Trình tự mìn thật (đúng thứ tự đã đạp):

    1. Upload sources...failed — thiếu storage.objectViewer (SA không đọc được chính file zip nó vừa upload)
    2. Building Container...failed với log rỗng hoàn toàn — thiếu logging.logWriter. Lỗi kép: không ghi được log nên build fail, VÀ vì không có log nên CLI cũng không hiển thị được gì — rất dễ tưởng nhầm là bug của gcloud
    3. Build fail lần nữa ở bước ANALYZING — thiếu artifactregistry.writer (buildpack cần pull lại image nó vừa push để lấy digest; cấp writer chứ đừng cấp reader — reader sẽ dính lỗi write ở lần deploy update sau)
    4. Cấp đủ 3 role cùng lúc → deploy pass ngay lần kế

    Gỡ cả bãi mìn bằng 1 lệnh — chạy TRƯỚC lần deploy đầu tiên:

    export PROJECT_ID=$(gcloud config get-value project)
PROJECT_NUMBER=$(gcloud projects describe $PROJECT_ID --format='value(projectNumber)')
SA="${PROJECT_NUMBER}-compute@developer.gserviceaccount.com"
for ROLE in roles/storage.objectViewer roles/logging.logWriter roles/artifactregistry.writer; do
  gcloud projects add-iam-policy-binding "$PROJECT_ID" \
    --member="serviceAccount:${SA}" --role="$ROLE" --condition=None
done
    Mẹo nhận diện nhanh: build fail 20 giây nghĩa là gì?
Build fail vì thiếu IAM luôn chết RẤT NHANH (20-23 giây) — không phải kiểu compile chậm hay timeout. Thấy fail nhanh bất thường = nghi lỗi quyền trước tiên, đừng ngồi dò code.

    2.3 Bước 1 — Bật API và chuẩn bị thư mục

    gcloud services enable run.googleapis.com aiplatform.googleapis.com cloudbuild.googleapis.com
    export PROJECT_ID=$(gcloud config get-value project)
export REGION=us-central1
mkdir coffee-barista-agent && cd coffee-barista-agent

    🔴 MÌN: thư mục source không được nằm trong một git repo khác — gcloud run deploy --source . sẽ cuốn theo ngữ cảnh repo đó. Lần làm thật đã phải dời coffee-barista-agent/ ra khỏi repo chính trước khi deploy.

    2.4 Bước 2 — Tạo 4 file theo codelab gốc

    Tạo menu.json (8 món có name/description/price/tags/allergens), requirements.txt (google-adk + streamlit), agent.py (LlmAgent tên barista_agent, model Gemini Flash, tool get_menu, instruction cấm bịa món ngoài menu) và app.py (Streamlit chat + InMemoryRunner). Nội dung file đầy đủ lấy từ codelab gốc — chương này không chép lại code để khỏi lệch version, chỉ giữ phần bản gốc KHÔNG nói.

    Kiểm JSON trước khi đi tiếp:

    cat menu.json | python3 -m json.tool > /dev/null && echo "JSON hợp lệ!"

    2.5 Bước 3 — Service account riêng cho agent

    gcloud iam service-accounts create barista-agent-sa \
  --description="Service account for Coffee Barista ADK agent on Cloud Run" \
  --display-name="Barista Agent Service Account"
    gcloud projects add-iam-policy-binding $PROJECT_ID \
  --member="serviceAccount:barista-agent-sa@$PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/aiplatform.user"

    Lưu ý: đây là SA runtime của service (codelab có dạy). Còn bãi mìn #0 nằm ở SA build mặc định — 2 con khác nhau, cấp cho con này không cứu con kia.

    2.6 Bước 4 — Deploy

    gcloud run deploy coffee-barista \
  --source . \
  --region $REGION \
  --allow-unauthenticated \
  --labels dev-tutorial=codelab-streamlit-rag-adk \
  --command "/cnb/lifecycle/launcher" \
  --args "sh,-c,python3 -m streamlit run app.py --server.port=\$PORT --server.address=0.0.0.0 --server.enableCORS=false --server.enableXsrfProtection=false" \
  --service-account "barista-agent-sa@$PROJECT_ID.iam.gserviceaccount.com" \
  --set-env-vars GOOGLE_GENAI_USE_ENTERPRISE=TRUE,GOOGLE_CLOUD_PROJECT=$PROJECT_ID,GOOGLE_CLOUD_LOCATION=global

    Deploy thật mất 3-5 phút (khi đã gỡ mìn #0 — còn dính mìn thì fail sau ~20 giây).

    2.7 🔴 MÌN — khi build fail mà log RỖNG, lấy log thật ở đâu

    Cả hai lệnh chính thống đều có thể trả rỗng khi chính build đó không có quyền ghi log (mìn #2):

    gcloud builds log <BUILD_ID> --region=$REGION
gcloud logging read 'resource.type=build AND resource.labels.build_id=<BUILD_ID>'

    Đừng tưởng CLI hỏng. Mở thẳng URL Console mà gcloud run deploy in ra lúc fail — Console đọc build metadata ở tầng hạ tầng, luôn hiện được dòng lỗi thật (lần đó là chữ “missing role(s) roles/logging.logWriter” chỉ thấy được trên Console):

    https://console.cloud.google.com/cloud-build/builds;region=<region>/<BUILD_ID>?project=<PROJECT_NUMBER>

    2.8 Bước 5 — Test hành vi RAG

    Mở URL service Cloud Run trả về, hỏi 3 câu kiểm:

    1. “Recommend something strong and warm” → phải gợi ý món CÓ trong menu (Espresso Solo)
    2. “Do you have matcha frappuccino?” → phải từ chối lịch sự (món không có — RAG không bịa)
    3. “I’m lactose intolerant” → chỉ gợi ý món dairy-free

    2.9 Bước 6 — Dọn dẹp

    gcloud run services delete coffee-barista --region $REGION --quiet
gcloud iam service-accounts delete barista-agent-sa@$PROJECT_ID.iam.gserviceaccount.com --quiet

    2.10 Ôn nhanh

    Q: Trên project GCP mới, vì sao deploy --source . fail tới 4 lần dù code đúng?
- Cloud Run không hỗ trợ Streamlit
-* Service account build mặc định không còn được tự cấp quyền rộng — thiếu 3 role, mỗi lỗi chỉ lộ sau khi vá lỗi trước
- Region chọn sai
E: Google chuyển sang "secure by default" — SA mặc định của Compute Engine không còn role Editor. Phải tự cấp storage.objectViewer + logging.logWriter + artifactregistry.writer.

Q: Build fail sau đúng ~20 giây, log rỗng cả trên CLI. Nghi ngờ đầu tiên nên là gì?
- Code Python có bug
- Mạng Cloud Shell chập chờn
-* Thiếu quyền IAM — fail-nhanh + log-rỗng là chữ ký của lỗi quyền, mở Cloud Build Console để thấy dòng lỗi thật
E: Thiếu logging.logWriter làm build vừa fail vừa không ghi được log — CLI trả rỗng nhưng Console luôn hiện được.

Q: Vì sao cấp artifactregistry.WRITER chứ không phải READER?
-* Buildpack cần pull lại image vừa push để lấy digest, và các lần deploy update sau còn cần ghi tiếp — writer bao luôn read
- Reader đắt tiền hơn
- Không có role reader trong GCP
E: Cấp reader thì lần deploy đầu qua nhưng lần update sau dính lỗi write — vá một lần cho đủ.
