    3  AI Agent với Gemini và BigQuery MCP server trên Cloud Run

    Làm thật 2 hồi (Hack2Skill GenAI Academy, Track 2): 2026-08-07 thử nhánh Gemma GPU — kẹt quota ngay cửa (mìn đắt giá nhất chương, kể ở cuối); 2026-08-14 hoàn thành trọn bản Gemini + BigQuery MCP — deploy pass ngay lần đầu nhờ bài IAM của chương 1, chỉ dính 1 quả mìn 403 runtime.

    Mục tiêu: dựng data agent (ADK + Gemini) tự truy vấn BigQuery qua MCP server có sẵn của Google — hỏi bằng tiếng người, agent tự chuỗi tool list_table_ids → get_table_info → execute_sql_readonly trên dataset public new_york_citibike (~58,9 triệu chuyến xe đạp).

    3.1 Tiến độ của bạn

    # Chuẩn bị
- Bật 5 API (run, cloudbuild, artifactregistry, bigquery, aiplatform)
- Đã cấp 3 role IAM build từ chương 1 (nếu project mới)
# Dựng agent
- Viết agent.py (LlmAgent + McpToolset trỏ MCP managed của BigQuery)
- adk deploy cloud_run thành công
# Gỡ mìn runtime
- Cấp 3 role runtime cho SA compute (aiplatform.user + bigquery.jobUser + dataViewer)
- Chờ IAM propagate 60-120 giây rồi mới test lại
- Agent trả lời được câu hỏi về dữ liệu citibike

    3.2 Bước 1 — Bật API

    gcloud services enable run.googleapis.com cloudbuild.googleapis.com \
  artifactregistry.googleapis.com bigquery.googleapis.com aiplatform.googleapis.com

    Nếu là project mới: cấp luôn 3 role IAM build như MÌN #0 của chương 1 — lần làm thật Track 2 đã cấp trước và không dính lại lỗi build nào, chứng minh bài học “cấp đủ 1 lượt” đúng.

    3.3 Bước 2 — Viết agent

    Điểm ăn tiền của bài này: không phải dựng MCP server nào cả — BigQuery có MCP endpoint managed sẵn của Google. Trong agent.py, McpToolset chỉ cần trỏ:

    url = "https://bigquery.googleapis.com/mcp"
tool_filter = ['get_dataset_info', 'list_table_ids', 'get_table_info', 'execute_sql_readonly']

    Auth bằng ADC token qua header (Authorization: Bearer … + x-goog-user-project). Giữ execute_sql_readonly trong tool_filter (không cấp quyền write) — đó là chốt an toàn của bài. Code đầy đủ lấy từ codelab gốc; nhớ thêm __init__.py chứa from . import agent.

    3.4 Bước 3 — Deploy bằng adk CLI

    export GOOGLE_CLOUD_PROJECT=$(gcloud config get-value project)
export GOOGLE_CLOUD_REGION=us-central1
export GOOGLE_GENAI_USE_ENTERPRISE="True"
export GOOGLE_CLOUD_LOCATION="global"
    uv tool run --from google-adk adk deploy cloud_run \
    --with_ui --project $GOOGLE_CLOUD_PROJECT --region $GOOGLE_CLOUD_REGION \
    --service_name bq-data-agent --app_name data_agent data_agent -- \
    --allow-unauthenticated --max-instances 1 \
    --labels dev-tutorial=codelab-cloud-run-adk-gemini-bq-mcp \
    --set-env-vars GOOGLE_GENAI_USE_ENTERPRISE=True,GOOGLE_CLOUD_PROJECT=${GOOGLE_CLOUD_PROJECT},GOOGLE_CLOUD_LOCATION=${GOOGLE_CLOUD_LOCATION}
    gcloud run services describe bq-data-agent --region us-central1 --format 'value(status.url)'

    3.5 🔴 MÌN — deploy XANH vẫn 500: lỗi runtime không hiện lúc deploy

    Lần làm thật: deploy pass ngay, container healthy, mở URL sống — nhưng hỏi agent câu đầu tiên là HTTP 500. Moi log mới ra lỗi thật:

    403 PERMISSION_DENIED. Permission 'aiplatform.endpoints.predict' denied

    Gốc: service account runtime của Cloud Run (SA compute mặc định) không có quyền gọi Vertex AI — service deploy được nhưng chết đúng lúc agent gọi model. Lệnh moi log khi gặp 500:

    gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="bq-data-agent" AND severity=ERROR' --limit 5 --format json

    Fix — cấp 3 role runtime 1 lượt (cho SA compute, không phải account người):

    PN=$(gcloud projects describe $GOOGLE_CLOUD_PROJECT --format='value(projectNumber)')
for R in roles/aiplatform.user roles/bigquery.jobUser roles/bigquery.dataViewer; do
  gcloud projects add-iam-policy-binding $GOOGLE_CLOUD_PROJECT \
    --member="serviceAccount:${PN}-compute@developer.gserviceaccount.com" \
    --role="$R" --condition=None
done

    🔴 MÌN TRONG MÌN — IAM propagate KHÔNG tức thời: retry sau ~40 giây vẫn 500; lần làm thật phải chờ tổng cỡ 60-120 giây (poll mỗi 20 giây) mới HTTP 200. Đừng vội kết luận “fix sai” khi mới thử lại 1 lần.

    3.6 Bước 4 — Test agent bằng curl (không cần mở UI)

    SVC=$(gcloud run services describe bq-data-agent --region us-central1 --format 'value(status.url)')
curl -s "$SVC/list-apps"
    curl -s -X POST "$SVC/apps/data_agent/users/u1/sessions/s1" -H "Content-Type: application/json" -d '{}'
    curl -s -X POST "$SVC/run" -H "Content-Type: application/json" -d '{
  "app_name":"data_agent","user_id":"u1","session_id":"s1",
  "new_message":{"role":"user","parts":[{"text":"What data do you have?"}]}}'
    Vì sao /run trả về cả một mảng dài mà không thấy câu trả lời đâu?
Response là MẢNG EVENT (từng bước tool-call của agent) — câu trả lời thật là text của event role=model CUỐI CÙNG. Và phải tạo session (lệnh POST sessions ở trên) TRƯỚC khi gọi /run, không thì lỗi.

    Kết quả thật lần làm 2026-08-14: agent tự chuỗi list_table_ids → get_table_info → execute_sql_readonly và trả lời đúng — citibike_stations 2.509 dòng, citibike_trips ~58,9 triệu dòng.

    3.7 🔴 MÌN LỚN NHẤT TRACK 2 — nhánh Gemma GPU: quota chặn TRƯỚC tiền

    Bài Gemma (self-host Gemma 4 31B + vLLM trên Cloud Run GPU) đã setup trọn — project mới, 9 API, VPC + subnet riêng, service account, cấu hình vLLM fp8 — rồi chết ngay tại lệnh deploy:

    Quota violated: MemAllocPerProjectRegion requested: 85899345920 allowed: 42949672960
    • Project GCP mới mặc định chỉ được 40GiB RAM/region cho Cloud Run — codelab Gemma-31B đòi 80GiB. Fail ngay lúc validate, GPU chưa từng chạy → 0 đồng (Cloud Run chỉ tính tiền khi instance thật chạy).
    • Muốn làm bài GPU trên project mới: xin tăng quota MemAllocPerProjectRegion TRƯỚC vài ngày — form chờ Google duyệt, không tức thời. Đến buổi lab mới xin là trễ.
    • Hạ memory xuống ≤40GiB cho model 31B = rủi ro OOM cao, không đáng thử.

    3.8 Ôn nhanh

    Q: Deploy Cloud Run xanh, container healthy, nhưng hỏi agent là HTTP 500. Nghi gì trước?
- Code agent.py sai cú pháp
-* Service account RUNTIME thiếu quyền gọi Vertex AI/BigQuery — lỗi chỉ nổ khi agent thật sự gọi model, không nổ lúc deploy
- MCP server của Google sập
E: Deploy chỉ kiểm container chạy được; quyền gọi aiplatform/bigquery của SA compute mặc định là chuyện lúc runtime. Moi log bằng gcloud logging read severity=ERROR.

Q: Vừa cấp role IAM xong, thử lại sau 40 giây vẫn 500. Kết luận đúng là gì?
- Fix sai role rồi, đổi role khác
-* IAM propagate mất 60-120 giây — poll thêm vài lần nữa rồi mới kết luận
- Phải redeploy service thì role mới ăn
E: Lần làm thật retry 40s vẫn fail, chờ tổng 60-120s (poll mỗi 20s) thì HTTP 200 — không cần redeploy.

Q: BigQuery MCP server trong bài này dựng ở đâu?
- Tự dựng container MCP server riêng trên Cloud Run
- Chạy local trong Cloud Shell
-* Không dựng gì cả — dùng endpoint MANAGED sẵn của Google: https://bigquery.googleapis.com/mcp
E: McpToolset trỏ thẳng endpoint managed, auth bằng ADC token; chỉ lọc tool readonly làm chốt an toàn.

Q: Vì sao bài Gemma GPU fail mà không tốn đồng nào?
-* Quota memory chặn ngay lúc validate — GPU chưa từng khởi động, Cloud Run chỉ tính tiền khi instance thật chạy
- Google miễn phí GPU cho codelab
- Đã kịp bấm huỷ trước khi bị tính tiền
E: "Quota đi trước tiền" — project mới mặc định 40GiB/region, bài đòi 80GiB, deploy chết từ cửa kiểm tra.
