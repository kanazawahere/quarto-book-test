    4  Personal Agent với sandbox trên Cloud Run — trợ lý quản lý quán cà phê

    Làm thật 2026-08-21 (Hack2Skill Track 3, đã nộp và được duyệt). Bản gốc: codelab của Google. Bài này KHÁC hẳn 2 chương trước: agent chạy code trong sandbox ngay bên trong service Cloud Run (--sandbox-launcher), chat qua WebSocket UI, và đọc/ghi Google Sheets — kéo theo một loạt mìn không dính gì tới GCP mà dính tới… copy-paste và Google Drive.

    Kết quả thật: service sống, chat với agent phân tích dữ liệu bán hàng POS-2025 trong Sheet rồi tự ghi việc cần làm vào tab TODO-2026 — xác nhận bằng mắt trên spreadsheet.

    4.1 Tiến độ của bạn

    # Chuẩn bị
- Bật 5 API (thêm sheets.googleapis.com so với 2 bài trước)
- Cấp 3 role IAM build (bài chương 1) nếu project mới
# Service account + Sheet
- Tạo SA riêng coffee-shop-agent-sa + cấp aiplatform.user
- Tạo Google Sheet, đặt tab dữ liệu POS-2025
- SHARE sheet cho email của service account (bước hay quên nhất)
# Code + Deploy
- Chép code từ codelab — QUÉT U+00A0 + py_compile trước khi build
- gcloud beta run deploy --sandbox-launcher thành công
- Chat thử, xác nhận agent ghi được vào tab TODO

    4.2 Bước 1 — API và service account riêng

    Bài này thêm Sheets API so với 2 chương trước:

    gcloud services enable run.googleapis.com cloudbuild.googleapis.com \
  artifactregistry.googleapis.com sheets.googleapis.com aiplatform.googleapis.com

    Tạo SA riêng làm runtime (least-privilege — không xài SA compute mặc định):

    export SA_NAME=coffee-shop-agent-sa
export GOOGLE_CLOUD_PROJECT=$(gcloud config get-value project)
export SERVICE_ACCOUNT_ADDRESS=$SA_NAME@$GOOGLE_CLOUD_PROJECT.iam.gserviceaccount.com
gcloud iam service-accounts create $SA_NAME \
  --description="Service account for the Coffee Shop Agent Codelab" \
  --display-name="Coffee Shop Agent SA"
gcloud projects add-iam-policy-binding $GOOGLE_CLOUD_PROJECT \
  --member="serviceAccount:$SERVICE_ACCOUNT_ADDRESS" --role="roles/aiplatform.user"

    Lần làm thật cấp sẵn 3 role build của chương 1 → cả phiên không dính một lỗi GCP nào, deploy pass ngay lần đầu — lần thứ 3 liên tiếp chứng minh bài “cấp đủ 1 lượt”.

    4.3 Bước 2 — Tạo Sheet và SHARE cho service account

    Tạo sheet mới (sheets.new), dán dữ liệu POS mẫu từ codelab, đổi tên tab thành POS-2025, lấy SPREADSHEET_ID từ URL.

    4.4 🔴 MÌN — SA không thấy sheet nếu không được share

    Quyền đọc/ghi Sheet không đi theo IAM role nào cả — nó đi theo nút Share như share cho một người thường. Phải share sheet cho đúng địa chỉ coffee-shop-agent-sa@<project>.iam.gserviceaccount.com, không thì agent gọi Sheets API sẽ không thấy file dù có bao nhiêu role đi nữa.

    Mìn phụ (cho ai share sheet bằng script/automation): dialog Share nằm ở đâu?
Dialog Share của Google Sheets nằm trong IFRAME riêng (URL chứa "driveshare") — mọi selector ở page chính sẽ timeout. Lần làm thật tốn ~6 lần thử mới tìm ra: phải liệt kê frames, tìm frame driveshare, thao tác bên trong frame đó. Share tay bằng chuột thì không sao.

    4.5 🔴 MÌN — copy code từ trang codelab dính ký tự tàng hình U+00A0

    Lỗi thật nguyên văn khi chạy code vừa chép từ trang codelab:

    SyntaxError: invalid non-printable character U+00A0   (main.py line 25)

    Trang codelab render space thành non-breaking space (U+00A0) — mắt nhìn y hệt space thường, Python thì chết. Quét và kiểm TRƯỚC khi build (đỡ tốn nguyên một vòng Cloud Build chỉ để phát hiện SyntaxError):

    python3 -c "content=open('main.py').read(); open('main.py','w').write(content.replace(' ',' '))"
python3 -m py_compile main.py && echo "SYNTAX OK"

    4.6 Bước 3 — Deploy với sandbox

    export REGION=us-central1
export SPREADSHEET_ID=<id-sheet-của-bạn>
gcloud beta run deploy coffee-mgr-agent \
    --source=. \
    --region=$REGION \
    --sandbox-launcher \
    --max-instances=1 \
    --session-affinity \
    --allow-unauthenticated \
    --no-cpu-throttling \
    --labels dev-tutorial=codelab-cloud-run-personal-agent-coffee-shop \
    --set-env-vars GOOGLE_GENAI_USE_VERTEXAI=1,GOOGLE_CLOUD_PROJECT=$GOOGLE_CLOUD_PROJECT,GOOGLE_CLOUD_LOCATION=global,SPREADSHEET_ID=$SPREADSHEET_ID \
    --service-account $SERVICE_ACCOUNT_ADDRESS --quiet

    Vì sao các flag này (thứ bản gốc lướt qua):

    • --sandbox-launcher: trong container có binary /usr/local/gcp/bin/sandbox — agent chạy Python/shell cách ly bên trong service; code codelab tự phát hiện chạy local (IS_LOCAL_MODE) thì bỏ sandbox.
    • --session-affinity + --max-instances=1: chat WebSocket giữ state in-memory — nhiều instance là mất session giữa chừng.
    • Có Dockerfile trong source → Cloud Build dùng Dockerfile (“Building using Dockerfile”), không phải buildpack như 2 bài trước.

    Mẹo: URL service đoán được trước cả khi deploy xong — https://<service>-<projectNumber>.<region>.run.app.

    4.7 Bước 4 — Chat thử

    Mở URL service → UI chat. Kịch bản thật đã chạy: nhờ agent phân tích dữ liệu bán hàng POS-2025 để chuẩn bị cho mùa tốt nghiệp 2026 → agent đọc sheet, phân tích, hỏi xác nhận → trả lời “Yes” → agent tự tạo tab TODO-2026 và ghi danh sách việc vào đó. Mở spreadsheet xác nhận bằng mắt.

    4.8 Ôn nhanh

    Q: Agent gọi Sheets API nhưng không thấy spreadsheet. Đã cấp roles/aiplatform.user rồi. Thiếu gì?
- Thiếu roles/sheets.editor ở tầng project
-* Chưa SHARE sheet cho email của service account — quyền sheet đi theo nút Share, không theo IAM role
- Chưa bật Drive API
E: Service account như một "người dùng" — phải được share file y như share cho đồng nghiệp.

Q: Code chép từ trang codelab chạy ra "SyntaxError: invalid non-printable character U+00A0". Chuyện gì?
- File bị hỏng khi tải
-* Trang codelab render space thành non-breaking space — mắt không phân biệt được, phải replace U+00A0 rồi py_compile trước khi build
- Python version quá cũ
E: Mìn kinh điển khi copy code từ trang web. Luôn py_compile trước khi deploy, đỡ tốn 1 vòng Cloud Build.

Q: Vì sao bài này bắt buộc --session-affinity và --max-instances=1?
-* Chat WebSocket giữ session in-memory — request rơi vào instance khác là mất sạch hội thoại
- Để tiết kiệm tiền
- Sandbox chỉ chạy được 1 instance
E: InMemorySessionService sống trong RAM của đúng 1 instance; affinity ghim client vào instance đó.
